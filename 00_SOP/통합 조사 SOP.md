### 4-0. 기존 목록 로드 (L0)

- 검색마다 제외 목록을 다시 읽거나 복사하지 않는다.
- **조사 기간**은 "직전 조사일 다음날 ~ 오늘"로 잡는다.

### 4-1. K-Startup 오픈 API (L1, 트랙 B)
- **End Point:** `https://apis.data.go.kr/B552735/kisedKstartupService01/getAnnouncementInformation01` (세부 기능명을 반드시 붙인다)
- **인증키:** 환경 변수 `KSTARTUP_API_KEY`. **문서·결과·커밋·출력 로그에 인증키를 적지 않는다** (curl 명령을 `echo`하거나 URL을 출력하지 않는다).
- `type=json`을 넣어도 XML로 응답하므로 처음부터 XML로 파싱한다.
- `numOfRows=100`, **1페이지만** 호출한다. (1페이지에 약 한 달 치 공고가 들어 있고, 아직 접수가 시작되지 않은 공고도 섞여 있다)
- **호출은 `curl`로 한다** (클라우드 프록시 인증서를 curl이 자동으로 쓴다). 결과 XML은 저장소 밖 임시 폴더에 받는다: `curl -s -o "$TMPDIR/kstartup.xml" "…?serviceKey=${KSTARTUP_API_KEY}&page=1&perPage=100&numOfRows=100"`. XML은 `<item>` 아래 `<col name="…">` 형식이며, 주요 필드는 `biz_pbanc_nm`(사업명), `pbanc_rcpt_bgng_dt`/`pbanc_rcpt_end_dt`(YYYYMMDD), `supt_regin`, `aply_trgt`, `biz_enyy`(업력), `biz_trgt_age`, `pbanc_ntrp_nm`, `pbanc_sn`이다.
- 스크립트 한 번으로 호출 → 파싱 → 기간·지역·자격 필터 → 요약 출력까지 처리한다. 스크립트·XML은 커밋하지 않는다.
- `k-startup.go.kr` 상세 페이지는 JS 렌더링 전용이라 직접 읽지 않는다. API 데이터로 부족하면 웹 검색으로 보완한다.
- 실패하면 0-1에 따라 대체한다.

> **접속 방법 (2026-09-30 테스트 결과):** 위비티는 검색 URL `https://www.wevity.com/?c=find&s=1&sw=AI`로 바로 목록을 읽을 수 있고, 첫 통합 조사에서 누락분을 찾아낸 유일한 정보원이었다. **L2는 위비티부터** 본다. crowlly는 홈이 아니라 `https://crowlly.xyz/competitions`를 읽는다. 정보터는 `thinkyou.co.kr/mobile/info_room/6823/` 취합 글(주기적으로 갱신)을 읽는다. aichallenge4all.or.kr은 JS 렌더링이라 직접 읽을 수 없으므로 웹 검색 결과로 대신한다.
>
> **클라우드에서는** 위 URL을 `WebFetch`로 연다. 네트워크 허용 목록에 없어 막히면 0-1에 따라 `WebSearch` + `allowed_domains`로 대신한다 (예: 위비티 → `allowed_domains: ["wevity.com"]`, 검색어 `AI 공모전 접수중`).
>
> 과거 조사에서 실제 결과를 많이 낸 정보원: 트랙 A는 aichallenge4all·위비티·링커리어, 트랙 B는 K-Startup API가 압도적(22회 인용)이다. 시간이 부족하면 이 정보원부터 확인한다. 이벤터스(event-us.kr)는 교육·행사의 **접수처**로 자주 쓰이므로 참고링크로는 허용하지만 탐색 대상은 아니다.

### 4-3. 트랙별 카테고리 검색 (L3)
검색어는 OR로 묶어 **트랙 A 3개, 트랙 B 1개 이내**로 수행한다.
- **A-1 영상·이미지·디자인:** `"생성형 AI" OR "AI 영상" OR "AI 숏폼" OR "AI 이미지" OR "AI 아트" 공모전 {연도}년 접수중`
- **A-2 아이디어·프롬프트:** `"AI 활용" OR "프롬프트" OR "ChatGPT" 아이디어 공모전 OR 챌린지 {연도}년`
- **A-3 서비스·음악:** `"AI 에이전트" OR "AI 음악" OR "AI 로고송" 공모전 OR 경진대회 {연도}년`
- **B-1 지역 타겟:** `"예비창업자" "서울" OR "은평" 지원 모집 공고 {연도}년 {월}월`

### 4-4. 공통 변형어·전국 단위 검색 (L4, 두 트랙 공유)
검색어 **2개 이내**로 수행하고, 결과를 2장의 분류 원칙에 따라 A/B로 나눈다.
- `"AI" OR "인공지능" 경진대회 OR 챌린지 OR 해커톤 OR 오디션 OR 어워드 OR 데모데이 {연도}년 {월}월 모집`
- `중소벤처기업부 OR 창업진흥원 OR 과학기술정보통신부 OR 문화체육관광부 OR KOCCA OR NIPA 모집 공고 {연도}년 {월}월`
- 그 해의 트렌드 키워드(AI, 소셜벤처, 로컬크리에이터, 딥테크 등)를 조합해 특별 트랙을 발굴한다.

### 4-5. 교차 검증 및 상세 수집 (L5)
- 모든 결과를 **중복 제거**하고, L0 목록에 있는 항목은 "이미 기록된 항목"으로 보낸다.
- 신규 후보만 공식 URL을 열어 템플릿 항목을 채운다. 검색 결과만으로 정보가 충분하고 공식 도메인(k-startup.go.kr, sba.seoul.kr, *.go.kr 등)이면 URL 열람을 생략할 수 있다.
- **추정 URL을 만들어 넣지 않는다.**
- 웹 검색 결과에는 **지난 회차 공고**(전년도, 이미 마감된 상반기 공고)가 많이 섞인다. URL을 열기 전에 검색 요약의 연도·마감일을 먼저 보고, 지난 공고면 열지 않고 "사전 필터링 제외"에 한 줄로 적는다.
- 체크리스트:
  - [ ] 마감일이 남았는가?
  - [ ] 공통 + 트랙별 제외 기준에 걸리지 않는가?
  - [ ] 연령 제한을 **공고 원문**에서 확인했는가? (1-0 연령 경계표 기준, 검색 요약만 믿지 않는다)
  - [ ] (A) AI 활용 범위(결과물 생성 가능 / 기획 보조만 / AI 필수)를 확인했는가? 부문별로 다르면 부문별로 적는다 (예: 숏폼 허용·사진 금지)
  - [ ] (A) 저작권 귀속 조건을 확인했는가?
  - [ ] (A) 적합도 등급(S/A/B/C)을 매겼는가?
  - [ ] (B) 예비창업자 신청 가능 여부와 지원금액을 확인했는가?
  - [ ] (B) 중복 수혜 제한 조항을 확인했는가?
  - [ ] 트랙 분류가 확정되었는가?
- 직전 조사 기간에 공고되었는데 놓친 항목을 이번에 발견하면 신규로 기록하되 "🔁 이전 조사 누락분" 표시를 붙인다.

### 4-6. 추천 공고 필터링 (L6, 조사의 마지막 단계)
L5까지 끝나면 **이번 회차 신규 + "이미 기록된" 전체**에서 할 만한 공고를 추려 **추천 목록**에 더한다. 추천 목록에 있는 것이 곧 추천 공고이므로 별도의 추천 상태 값은 두지 않는다. 캘린더에는 추천 목록에 있는 항목만 둔다.

**① 자격 재확인**
- 이전 회차에서 잘못 포함된 항목이 없는지 1-0 연령 경계표와 3장 제외 기준으로 다시 본다 (2026-09-30 첫 L6에서 대학생 전용·학생부 전용 2건을 찾아냄).
- 걸리면 "이미 기록된" 표에서 빼고 "사전 필터링 제외"에 사유를 적는다.

**② 할 만한 것 추리기**
| 트랙 | 추천 기준 | 제외 기준 |
|---|---|---|
| 🏆 공모전 | 적합도 **S·A·B**. 수상 인원이 많을수록(20명 이상), 장관상급일수록 가산 | 적합도 **C**, 상금 없음·미정이면서 장관상급도 없는 것, 상품권·기프트카드 위주, 최고 상금 100만 원 미만, 본인 출연 필수 |
| 🚀 지원사업 | 사업화 자금·상금이 있는 경진대회, 우대 분야와 맞는 사업, 진행 중 프로젝트와 연결되는 **무료 교육·멘토링·네트워킹** | 아이템이 없는 조건부 후보, 은평 외 입주 공고(실익이 낮을 때) |

- **동시 진행 수는 추천 여부에 영향을 주지 않는다.** 한 주에 2개가 넘게 몰려도 기준에 맞으면 모두 추천한다. WIP 한도(7-1)는 사용자가 실제로 착수할 항목을 고를 때만 적용한다.
- 같은 결과물을 재활용할 수 있는 항목(같은 사업계획서로 경진대회 2곳, 같은 광고 소재로 CF 공모전 2곳)은 추천 이유에 함께 적는다.

**③ 결과 반영**
- 직전 결과 문서의 "🎯 추천 공고" 표를 **그대로 이어받고** 새로 추린 항목을 더한다. **마감이 지난 추천 공고도 지우지 않고** 마감일 칸에 `(마감)`을 붙여 남긴다.
- 6장 규칙에 따라 **구글 캘린더를 추천 목록과 맞춘다.**

### 4-7. 실행 효율 원칙
- **서브에이전트를 만들지 않는다.** 메인 에이전트가 L0 → L6을 순차로 수행한다. (2026-08-27 병렬 에이전트 4개 실행 시 제외 목록 중복과 할당량 초과로 토큰이 과도하게 소비됨)
- **목표 예산:** 파일 읽기 3회 이내, 웹 검색 8회 이내, URL 열람 10회 이내, 스크립트 실행 2회 이내 (API 1 + 예비 1). 캘린더는 커넥터 호출이라 스크립트 예산에 넣지 않는다.
  - 2026-09-30 첫 통합 조사 실제 사용량: 파일 읽기 1, 웹 검색 8, URL 열람 9, 스크립트 3 (그중 1회는 SSL 오류로 실패). 검색과 URL 예산이 거의 다 찼으므로, 검색은 L2 위비티에서 나온 후보를 확인하는 데 우선 쓴다.
  - 0-1에 따라 `WebFetch` 대신 `WebSearch`로 대체한 호출은 URL 열람 예산에서 차감한다 (웹 검색 예산을 잡아먹지 않게).
- 동일 결과가 예상되는 유사 검색어는 한 번만 검색한다.

### 5-6. 커밋·푸시
- 모든 문서·백업을 만든 뒤 `main`에 한 번에 커밋한다. 메시지: `[YYYY-MM-DD] 통합 조사: 🏆 N건 · 🚀 N건 신규, 추천 +N`
- 푸시는 `git push -u origin main`. 네트워크 오류일 때만 2s·4s·8s·16s 간격으로 최대 4회 재시도한다. 충돌이 나면 `git pull --no-rebase`로 병합한 뒤 다시 푸시한다 (사용자가 로컬에서 고친 내용을 덮어쓰지 않는다).
- 커밋 전 `git diff --cached`에 인증키 문자열이 없는지 확인한다.

## 6. 구글 캘린더 연동 (Google Calendar 커넥터)

> **대상 캘린더: 개인 캘린더 `ljki87@gmail.com` 하나뿐.** 가족 캘린더(`family…@group.calendar.google.com`)에는 절대 쓰지 않는다. 모든 호출에 `calendarId: "ljki87@gmail.com"`을 명시한다.
> **캘린더에는 L6 추천 목록에 있는 항목만 둔다.** 조사에서 찾았지만 추천하지 않은 항목은 결과 문서에만 기록한다.
> 미리 알림(Reminders)·Google Tasks는 사용하지 않는다 (2026-09-30 결정).

### 6-1. 트랙별 구분
애플 캘린더의 별도 캘린더 4개 대신, **제목 접두어 + 이벤트 색상**으로 구분한다.

| 구분 | 제목 접두어 | colorId (색) |
|---|---|---|
| 🏆 공모전 시작 | `[공모전·시작]` | `5` (바나나) |
| 🏆 공모전 마감 | `[공모전·마감]` | `6` (귤) |
| 🚀 지원사업 시작 | `[창업·시작]` | `2` (세이지) |
| 🚀 지원사업 마감 | `[창업·마감]` | `10` (바질) |

| 항목 | 🏆 공모전 | 🚀 지원사업 |
|---|---|---|
| 설명(description) | 카테고리 / 적합도 / 참가자격 / 시상내역 / AI 활용 범위 / 제출물 | 지원대상 / 지원내용 / 신청방법 |
| 제출 목표 | 마감일 (D-3 완료 목표, 7-1) | **D-1 18:00** (서버 폭주 대비, 7-1) |

### 6-2. 이벤트 형식
- 이벤트 1: `[공모전·시작] 항목명` 또는 `[창업·시작] 항목명`, 접수 시작일, 종일
- 이벤트 2: `[공모전·마감] 항목명 (마감시간)` 또는 `[창업·마감] 항목명 (마감시간)`, 실제 마감일, 종일 (마감시간 표기는 선택)
- 접수 시작일이 조사일 이전이면 시작 이벤트는 만들지 않는다 (지난 날짜에 새 이벤트를 만들지 않는다).
- **종일 이벤트 날짜 형식 (2026-10-02 테스트로 확인):** `allDay: true`, `startTime: "YYYY-MM-DDT00:00:00Z"`, `endTime`은 **다음 날** `"YYYY-MM-DDT00:00:00Z"`. 구글은 종료일을 포함하지 않으므로 이렇게 해야 하루짜리가 된다.
  - ⚠️ `+09:00` 오프셋을 붙이면 UTC로 바뀌며 **하루 앞당겨진다** (10월 3일 → 10월 2일). 반드시 `Z`를 쓴다.
- `description` 형식 (줄바꿈은 실제 줄바꿈 문자로 넣는다. `\n` 문자열을 넣으면 그대로 표시된다):
  ```
  🔗 공고 원문 URL
  카테고리: … / 적합도: …      (지원사업은 지원대상: …)
  …나머지 필드 한 줄씩
  #opp-sop
  ```
  첫 줄은 공고 URL, **마지막 줄은 반드시 `#opp-sop` 마커**다. 이 마커로 이 SOP가 만든 이벤트만 찾고 지운다.
- `useDefaultReminders: false` + `overrideReminders: [{"method":"popup","minutes":540}]`(전날 15:00 알림)은 **마감 이벤트에만** 넣는다. 시작 이벤트는 알림 없음(`useDefaultReminders: false`, override 없음).
- 생성·삭제 시 `notificationLevel: "NONE"`.

### 6-3. 추천 목록과 동기화
1. **조회:** `list_events`에 `calendarId: "ljki87@gmail.com"`, `fullText: "#opp-sop"`, `startTime`=조사일 00:00 KST, `endTime`=조사일+400일, `pageSize: 250`으로 **한 번에** 읽는다 (`nextPageToken`이 있으면 이어서 읽는다).
2. **추가:** 추천 항목 중 같은 제목의 이벤트가 없는 것만 만든다. 있으면 건너뛴다. 날짜만 바뀐 경우(마감 연장 등)는 기존 이벤트를 지우고 새로 만든다.
3. **삭제:** 조회 결과 중 추천 목록에 없는 것을 지운다. 이전 회차에 추천했다가 이번에 빠진 항목도 여기서 정리된다.
4. **지난 이벤트·마커 없는 이벤트는 건드리지 않는다.** 조사일 이전 날짜의 이벤트는 기록으로 남기고, `#opp-sop` 마커가 없는 이벤트(사용자가 직접 만든 일정, 7-3 타임블로킹 포함)는 제목이 비슷해도 지우지 않는다.
5. 삭제 전에 지울 이벤트의 제목·날짜·설명·이벤트 ID를 `99_아카이브/캘린더 삭제 백업/[YYYY-MM-DD] 캘린더 삭제 백업.tsv`에 저장한다 (구글 캘린더 휴지통은 30일 뒤 비워진다). 삭제할 것이 없으면 파일을 만들지 않는다.
6. 처음 클라우드로 실행할 때 애플 캘린더에 남은 이벤트는 이 SOP가 관리하지 않는다. (사용자가 직접 정리)

### 6-4. 조건부 후보
L6에서 추천된 조건부 후보만 등록한다. 설명 둘째 줄의 지원대상 끝에 `(조건부: …)`로 조건을 적는다.
